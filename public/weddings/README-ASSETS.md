## Supabase platform (implemented)

Migrations in `supabase/migrations/` (apply in order):

1. `0001_platform_schema.sql` — tables, RLS, storage bucket, expiry trigger
2. `0002_seed_demo_data.sql` — 5 templates + 5 demo weddings (generated by `scripts/generate-seed.mjs`)
3. `0003_expiry_automation.sql` — pg_cron jobs: mark expired daily 03:00 UTC, purge via edge function 03:15 UTC

Tables:
- `admin_users` — Supabase Auth users with admin/owner role (`is_admin()` RLS helper)
- `templates` — registry metadata (render logic stays in code: `components/weddings/templates/`)
- `wedding_websites` — slug (unique, validated), template FK, status draft/published/expired/deleted, wedding_date, expiry_days (default 7), custom_expires_at, computed expires_at, rsvp_enabled (default false)
- `wedding_content` — key/value JSONB per website (couple, events, venue, contacts, sections, hashtag, music, blessing, mantra)
- `wedding_images` — slot-based (`couple`, `gallery`, `event:<id>`), Supabase Storage paths or legacy `/weddings/*` paths
- `wedding_rsvps` — future-ready; guests can insert only into live RSVP-enabled sites; admins read
- `app_settings` — default_expiry_days (7), retention_days (30), cleanup_secret

Storage: public bucket `wedding-images` (10 MB, JPG/PNG/WebP/AVIF); uploads/deletes admin-only via RLS. Path convention `{websiteId}/{slot}-{ts}.{ext}`.

Expiry: public RLS blocks sites the moment `expires_at` passes. Cron marks status `expired`; the `cleanup-expired-websites` edge function hard-deletes sites (DB rows + storage files) `retention_days` after expiry. Soft-deleted sites purge on the same window.

## Admin auth

Supabase Auth (email/password) + `admin_users` membership. Middleware refreshes the session and gates `/admin/wedding-invitations/*`; `requireAdmin()` checks the admin row. Bootstrap the first owner with `supabase/setup-admin.sql` (set email + password first).

Env (`.env.local`, gitignored): `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` (publishable key). No service-role key in the app — admin writes run under the signed-in admin through RLS.

Public URLs: `yourdomain.com/<slug>` (root) and `/wedding-invitations/<slug>` (legacy path). Both load from Supabase; demo sample-data is an outage fallback only.
